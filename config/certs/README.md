# TLS: доверенные корневые сертификаты РФ

T-Invest API обслуживает TLS-сертификаты, выпущенные Российским национальным
удостоверяющим центром (НУЦ Минцифры РФ). Этих корневых сертификатов нет в
стандартных хранилищах доверия ОС/Python — поэтому соединение падает с ошибкой
проверки сертификата. Это **не баг API**, а отсутствие доверия к корневому CA.

## Решение

Не отключать проверку (`verify=False`), а **расширить доверие**:

1. Скачайте PEM-бандл Russian Trusted CA ( корневой + выпускающий НУЦ Минцифры )
   с официального ресурса — Госуслуги / портал `gosuslugi.ru/crt` либо
   `https://www.gosuslugi.ru/crt` (раздел «Сертификаты»).
2. Положите файл сюда под именем `russian_trusted_ca.pem`.
3. Бот подхватит его автоматически:
   * для gRPC-канала — `grpc.ssl_channel_credentials(root_certificates=...)`;
   * для произвольных HTTP-вызовов — через `REQUESTS_CA_BUNDLE` / `SSL_CERT_FILE`
     (см. `adapters/driven/tbank/tls.py`).

При отсутствии файла процесс **не стартует** в LIVE-режиме (fail-fast), если не
включён флаг `REDBOT_TBANK__INSECURE_TLS_DEV_ONLY=true` — а он, в свою очередь,
заблокирован валидатором в LIVE.

## Аварийный режим

`insecure_tls_dev_only=True` допустим только локально, только в sandbox/backtest.
Валидатор `Settings._forbid_insecure_tls_in_live` физически запрещает
сочетание `execution_mode=live` и этого флага.
