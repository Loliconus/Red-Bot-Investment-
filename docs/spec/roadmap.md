# Дорожная карта и статус разработки

План работ разбит на 8 этапов. Отметки — фактическое состояние ветки
`arena/01a0d5c9-red-bot-investment`.

## Этап 1 — Конфигурация и ядро ✅

- [x] `pyproject.toml`: PEP 621, ruff (14 правил), mypy strict, pytest с
      маркерами `sandbox`/`contract`, зависимости и индекс Т-Банка.
- [x] `config/`: настройки, keyring, structlog с редактированием секретов,
      дефолты стратегии, fail-fast валидация.
- [x] `core/domain/`: енамы, value objects, сущности, доменные события.
- [x] `core/ports/`: шесть портов-протоколов.
- [x] `core/analysis/`: ATR, OBV, VWAP, Fibonacci, корреляция, стакан,
      confluence-скор.
- [x] `core/risk/`: издержки, сайзинг, hard stop, инвалидация, time exit.
- [x] `core/strategy/`: режим рынка, сканер сетапов, тайминг, сборка плана.
- [x] `core/journal/`: снапшоты, разбор сделок, гипотезы, советы.

## Этап 2 — Слой приложения ✅

- [x] Шина событий с изоляцией ошибок подписчиков.
- [x] Юзкейсы: решение, мониторинг позиций, исполнение, сохранение снапшотов,
      обновление конфига, bootstrap БД, архивация, дневной отчёт,
      самоанализ.
- [x] `KillSwitch`: ручной + по дневному убытку.
- [x] `Scheduler`: циклы с backoff.
- [x] `composition.py`: сборка контекста по контуру запуска.

## Этап 3 — Драйвен-адаптеры ✅

- [x] `storage`: пул DuckDB, схема (11 таблиц), репозиторий, Parquet-архив,
      guard `is_select_only`.
- [x] `tbank`: TLS, мапперы, retry с идемпотентностью, gRPC-клиент, рыночные
      данные, брокер с блокировкой чужого счёта, менеджер стримов.
- [x] `sandbox`: адаптеры песочницы.
- [x] `backtest`: реплей истории и симулятор исполнения.

## Этап 4 — Драйвинг-адаптеры ✅

- [x] FastAPI + WebSocket GUI: статус, планы, позиции, журнал, гипотезы,
      анализ (walk-forward), конфиг, администрирование БД.
- [x] CLI: `run`, `db bootstrap`, `db stats`, `secrets set-token`.

## Этап 5 — Тесты ✅

- [x] Юнит-тесты ядра без внешних зависимостей: домен, индикаторы, риск,
      стратегия, журнал, конфиг, мапперы, retry, SQL-guard.
- [x] Контрактные тесты портов: `MarketData`, `OrderExecution`, `Repository`,
      `Archive` — один набор проверок на все реализации.
- [x] Интеграционные: composition root, Web GUI, сквозной бэктест-прогон.
- [x] `mypy` strict — чисто; `ruff check` и `ruff format` — чисто.

## Этап 6 — Эксплуатация в песочнице ⏳

- [ ] Получить токен песочницы, открыть счёт.
- [ ] Прогнать бота в контуре `SANDBOX` не менее 2 недель.
- [ ] Сверить логи ордеров с выпиской (реконсиляция).
- [ ] Проверить поведение kill switch на реальном контуре.

## Этап 7 — Валидация стратегии ⏳

- [ ] Набрать ≥ 30 сделок (минимум для гипотезы).
- [ ] Walk-forward проверка: efficiency ≥ 0.5 — приемлемо, < 0.3 — переобучение.
- [ ] Проверка на красные флаги: Sharpe > 3, MaxDD < 5%, WR > 80%, PF > 4.

## Этап 8 — Допуск в бой ⏳

Чек-лист перед `LIVE` (все пункты обязательны):

- [ ] Sandbox-эксплуатация без расхождений в реконсиляции.
- [ ] Walk-forward пройден.
- [ ] Kill switch проверен вручную.
- [ ] Дневной лимит убытка задан и протестирован.
- [ ] Токен боевого счёта лежит в keyring, не в `.env` и не в git.
- [ ] Резервная копия БД сделана.
- [ ] **Явное решение пользователя на запуск.**
- [ ] Первая неделя — минимальный размер позиции.

## Известные ограничения текущей реализации

| Ограничение | Почему | Что делать |
| :-- | :-- | :-- |
| Telegram-уведомления не реализованы | не входят в MVP | добавить адаптер `NotificationPort` |
| Индикаторы API (SMA/EMA/RSI/MACD/BB) не проверены на живом API | нужен токен | прогнать в sandbox |
| Схема БД версии 1 | ранняя стадия | миграции добавить перед LIVE |
| Решения принимаются по одному инструменту за вызов | проще трассировать | распараллелить при необходимости |
| Песочница Т-Инвест не заменяет бэктест | у неё нет истории | использовать `BacktestReplayAdapter` |
