# 00. Сводный конспект исследования

Дата: 2026-09-24. Источники — официальная документация T-Invest API, репозиторий
`invest-python` на `opensource.tbank.ru`, документация CPython 3.14/3.15,
исследования по бэктестингу и риск-менеджменту.

Подробности — в документах `01`–`05`. Здесь только выводы, которые меняют
принимаемые решения.

## Блок A. T-Invest API

1. **API — gRPC-first.** Прод: `invest-public-api.tbank.ru:443`, песочница:
   `sandbox-invest-public-api.tbank.ru:443`. REST оставлен для совместимости,
   но gRPC — основной путь (стримы, свечи, лимиты).
2. **Основной идентификатор инструмента — `instrument_uid`.** `FIGI` объявлен
   устаревшим и не поддерживается в опционах. Поле `instrument_id` универсально:
   принимает `instrument_uid`, `FIGI` или `TICKER_CLASSCODE` (`T_TQBR`).
3. **Деньги — это `Quotation` и `MoneyValue`** (`units` + `nano`, миллиардные
   доли). Время — protobuf `Timestamp` (UTC). Знак `units` и `nano` обязан
   совпадать, `|nano| < 999 999 999`.
4. **Цена ≠ стоимость.** Акции: `price × lot`; облигации: `price / 100 × nominal
   + НКД`; валюта: `price × lot / nominal` (у JPY/AMD/KZT `nominal = 100`);
   фьючерсы: `price / min_price_increment × min_price_increment_amount`.
5. **`quantity` — лоты.** Классическая ошибка №1 новичков: переданное число
   штук вместо лотов даёт заявку в 10/100/1000 раз больше запланированной.
6. **Идемпотентность обязательна.** `PostOrderRequest.order_id` — клиентский
   ключ; повтор с тем же ключом после успешного размещения → ошибка `30057`.
   Уникальность ключей отслеживается только **за последний месяц**.
7. **Два `order_id`.** В запросе — ключ идемпотентности, в ответе — биржевой id.
   Плюс `order_request_id` в ответе. В `getOrderState` по умолчанию ждут
   биржевой id; для клиентского ключа — `OrderIdType.ORDER_ID_TYPE_REQUEST`.
8. **Лимиты жёсткие и считаются суммарно по сервису и по всем счетам/токенам.**
   `postOrder` — 15/сек (900/мин), `cancelOrder`/`replaceOrder` — 300/мин,
   `getOrders` — 200/мин, котировки — 600/мин, стоп-заявки — 50/мин,
   `Bonds`/`Shares`/`Etfs`/`Futures`/`Options`/`GetAssets` — всего **15/мин**.
   Рекомендация вендора: ≤ 50 запросов/сек с одного адреса.
9. **Стримы дешевле unary.** 32 соединения на котировки, до 300 подписок в
   соединении, отправка стаканов/свечей не чаще раза в 100 мс. Свечи в стриме —
   сырые, с «корректирующими» свечами; для закрытых интервалов есть
   `waiting_close`.
10. **Историю берём батчами.** У `getCandles` лимит интервала зависит от
    таймфрейма (1 мин → до 1 дня, 1 час → до 3 мес, 1 день → до 6 лет). Готовый
    ZIP архив минутных свечей за год — `GetHistory` (обновляется раз в сутки).
11. **Торговый статус решает, можно ли вообще отправлять заявку.** 17 статусов.
    Рыночные заявки запрещены в `OPENING_PERIOD`, `CLOSING_PERIOD`,
    `DEALER_NORMAL_TRADING`, `DISCRETE_AUCTION` (разрешены только лимитные).
12. **Заявка дороже 30 млн ₽ через API невозможна** — требуется подтверждение
    по СМС. Дробим. В песочнице то же ограничение на пополнение.
13. **Порядок доставки исполнения не детерминирован между сервисами:**
    `OrderStateStream`/`GetOrderState` → `PositionsStream`/`GetPositions` →
    `PortfolioStream`/`TradeStream`/`GetPortfolio` → `GetOperationsByCursor`.
    Брокер — не строго консистентная система, значит обязательна сверка.
14. **Песочница ≠ бэктест.** В ней плечо 2 для всех, комиссия ровно 0,05 %,
    нет налогов, купонов и дивидендов, market-заявки исполняются по last price,
    а заявки не влияют на стакан. Прибыль в песочнице ничего не доказывает.

## Блок B. Python SDK

15. **Пакет называется `t-tech-investments`** и ставится из GitLab-реестра
    Т-Банка, а не с PyPI:

    ```bash
    pip install t-tech-investments \
      --index-url https://opensource.tbank.ru/api/v4/projects/238/packages/pypi/simple
    ```

    Нужны сертификаты МинЦифры (для РФ) либо `--trusted-host
    opensource.tbank.ru`; при проблемах с SSL — env `SSL_TBANK_VERIFY=True`.
16. **Неймспейс сменился трижды:** `tinkoff.invest` → `t_tech.invest` (0.3.0) →
    **`t_tech.invest.grpc`** (1.0.0). С 1.0.0 все аргументы методов обёрнуты в
    request-модели: `post_order(request=PostOrderRequest(...))`. Код из
    туториалов 2023–2024 гг. гарантированно не сработает.
17. **В репозитории SDK есть `AGENTS.md`, `.agents/skills/t-invest-python-sdk-bot-builder/SKILL.md`
    и `docs/ai/*`** — это официальный канон для агентов. Он прямо запрещает:
    вызов `post_order` из стратегии/LLM, `float` в расчётах, слепой retry
    мутации, смешение sync/async, ручную правку `*_pb2.py`.
18. **Режимы работы задаются явно:** `read-only`, `sandbox`, `production`,
    unit-тест, бэктест. Класс клиента (`Client` vs `SandboxClient`) сам по себе
    ещё не означает мутацию — режим определяет вызываемый метод.
19. **В utilities уже есть всё для денег:** `t_tech.invest.utils` →
    `quotation_to_decimal`, `decimal_to_quotation`, `money_to_decimal`,
    `decimal_to_money` (последняя принимает код валюты).
20. **Текущая версия SDK на момент исследования — 1.51.0**, ветка `master`
    активно развивается (в т.ч. добавляют документацию для LLM-агентов).

## Блок C. Python 3.14+

21. **Python 3.14.7 — актуальный стабильный выпуск**; 3.15.0rc2 вышел
    2026-09-01, финал — 2026-10-01. Значит: целевая версия проекта — 3.14,
    совместимость с 3.15 проверяем отдельной джобой в CI.
22. **Главные фичи 3.14, полезные боту:** отложенные аннотации (PEP 649/749,
    модуль `annotationlib`), t-строки (PEP 750 — безопасная подстановка в SQL/логи),
    сабинтерпретаторы в stdlib (PEP 734), `compression.zstd` (PEP 784 — дешёвое
    хранение тиков/свечей), интроспекция asyncio из CLI, официально
    поддерживаемый free-threaded билд (PEP 779), инкрементальный GC.
23. **В 3.15 стоит закладываться на:** `lazy import` (PEP 810), `frozendict`
    (PEP 814), `sentinel` (PEP 661), UTF-8 по умолчанию (PEP 686), распаковку в
    генераторах списков (PEP 798), `TypeForm` (PEP 747), «закрытый» `TypedDict`
    (PEP 728), профилировщик Tachyon (PEP 799).
24. **Стандартный туллинг 2026:** `uv` (окружение + зависимости + версии Python),
    `ruff` (lint и format вместо black+isort+flake8), `mypy`/`pyright`/`ty`
    (type check), `pytest`, `pre-commit`, `nox`/`uv --python` для матрицы версий,
    `structlog` для логов, `pydantic` на внешних границах (конфиг, LLM-ответ) и
    `msgspec`/dataclass для внутренних DTO.

## Блок D. Трейдинг

25. **Порядок разработки важнее модели:** сформулируй гипотезу → зафиксируй
    ≤ 5 параметров → разбей выборку (in-sample / hold-out, который открываешь
    **один раз**) → walk-forward с честными издержками → дефлируй Шарпа на число
    переборов → только потом песочница и реальные деньги.
26. **Число переборов обесценивает результат.** Три прогона уже способны дать
    ложную значимость; на 5 годах дневных данных нельзя пробовать больше ~45
    вариантов. Оружие: Deflated Sharpe Ratio, Probability of Backtest Overfitting,
    purged k-fold + embargo, CPCV.
27. **Красные флаги бэктеста:** Sharpe > 3, MaxDD < 5 %, > 30 параметров,
    < 100 сделок, win rate > 80 %, profit factor > 4, самая длинная серия
    убытков < 3.
28. **Сайзинг — это и есть риск-менеджмент.** База: фиксированная доля 1–2 %
    капитала на сделку, `Size = (Капитал × Риск %) / |Entry − Stop|`. Келли
    берём дробным (1/4–1/2) и только при 200+ подтверждённых сделках, с жёстким
    потолком 2–5 % и снижением риска при просадке.
29. **Метрики читают вместе, не по одной:** expectancy в R (> 0.3R — рабочая
    зона), profit factor (> 1.5), Sharpe (> 0.5 реально, > 2 — повод
    подозревать подгон), Sortino, Calmar (> 0.5), MaxDD, recovery factor.
    Win rate без R:R ничего не значит.
30. **Инфраструктура риска обязана пережить падение стратегии:** лимиты позиции,
    лимит убытка, лимит частоты заявок, kill switch **в отдельном процессе**,
    ежедневная реконсиляция с брокером. Kill switch в виде флага внутри
    стратегии не работает: он умирает вместе с ней.
31. **Специфика MOEX:** торговый день разбит на аукцион открытия (06:50–06:59),
    утреннюю сессию (07:00–09:49), аукцион основной сессии (09:50–09:59),
    основную сессию (10:00–18:49), аукцион закрытия (18:50–18:59), вечернюю
    сессию (19:05–23:49). Срочный рынок с 23.03.2026 — единая сессия
    09:50–23:50. Расчёты — **Т+1** с 31.07.2023. Сделки выходного дня относятся
    к следующему рабочему дню.
32. **Налоги РФ:** НДФЛ 13 % до порога 2,4 млн ₽ совокупного дохода за год и
    15 % сверх; дивиденды — 13/15 %; ИИС-3 даёт вычет на взнос (до 400 000 ₽/год
    базы, до 52 000 ₽ к возврату) и освобождение прибыли до 30 млн ₽ при
    закрытии, но минимальный срок — 5 лет (растёт до 10 лет к 2031 г.), до 3
    счетов одновременно. Комиссия брокера по рынку — примерно 0,01–0,3 %.
    Всё это надо зашить в бэктест, иначе «прибыльная» стратегия убыточна.
