# 04. Трейдинг: гайды, исследования, правила, метрики

Конспект того, что действительно влияет на выживаемость робота. Дата:
2026-09-24.

---

## 4.1. Жизненный цикл стратегии

Пять этапов (по классификации T-Invest API, совпадает с индустриальной
практикой):

1. **Сбор и анализ исторических данных** — котировки, свечи, максимальная
   глубина.
2. **Выдвижение гипотезы** — идея, выраженная в правилах или в обученной модели.
3. **Проверка на истории** — эмуляция торговли в прошлом, оценка доходности.
   Неудовлетворительно → назад к гипотезе.
4. **Проверка в реальном времени** — песочница. Она не учитывает влияния робота
   на рынок, но ловит ошибки интеграции.
5. **Реальная торговля** с мониторингом и корректировкой.

Ключевой принцип: **бэктест нужен, чтобы отбрасывать плохие модели, а не чтобы
улучшать хорошие**. Подгонка модели по результатам бэктеста — это переобучение.

## 4.2. Бэктест: как не обмануть себя

### Порядок операций важнее модели

Фиксируем **последовательность**, а не «умную модель»:

1. Сформулировать гипотезу **до** того, как коснулись данных.
2. Ограничить число параметров — **≤ 5**, максимум до 30 как абсолютный предел.
3. Разбить выборку: in-sample + **hold-out, который открывается ровно один раз**.
4. Walk-forward на скользящих окнах: оптимизируем на окне, тестируем на
   следующем, только out-of-sample куски идут в итоговую кривую.
5. Заложить реальные издержки: комиссия брокера, биржевой сбор, спред,
   проскальзывание, НКД по облигациям, налоги.
6. **Дефлировать Шарп** на число перебранных вариантов.
7. Проверить стабильность параметров: если «лучшие» параметры скачут между
   окнами — предела нет, это шум.

### Пять слоёв защиты от переобучения

| Инструмент | Что делает |
| :-- | :-- |
| **Purged k-fold CV** | удаляет из train те наблюдения, чьи метки пересекаются по времени с test |
| **Embargo** | запрещает train сразу после test-периода |
| **CPCV** (combinatorial purged CV) | даёт много независимых backtest-путей вместо одного |
| **Deflated Sharpe Ratio (DSR)** | корректирует Шарп на число проведенных испытаний |
| **Probability of Backtest Overfitting (PBO)** | доля сплитов, где IS-оптимум хуже медианы OOS; PBO > 0.5 ⇒ переобучение |

Эмпирика:

- На 5 годах дневных данных **нельзя пробовать больше ~45 вариантов** — иначе
  Шарп ≥ 1 получается случайно даже при истинном Шарпе ≤ 0.
- **Всего 3 прогона** способны создать иллюзию статистической значимости.
- 100 вариантов с сырым Шарпом 2.0 могут дать дефлированный Шарп около 0.5.

### Walk-forward

- Схема «оптимизируй на 12 месяцев → тестируй на 3» (4:1) — типичный старт.
- **Anchored** — начало окна зафиксировано, train растёт.
- **Rolling** — окно фиксированной длины скользит.
- Итоговая кривая капитала склеивается **только из OOS-сегментов**.

### Диагностические пороги

| Показатель | Порог | Что значит при нарушении |
| :-- | :-- | :-- |
| Deflated Sharpe | > 0.95 | результат выдерживает коррекцию на число испытаний |
| PBO | < 0.30 | низкая вероятность переобучения |
| Разрыв IS/OOS по Шарпу | < 30 % | приемлемая обобщаемость |
| Деградация Шарпа на walk-forward | < 50 % | стратегия адаптируется к режимам |

### Красные флаги бэктеста

| Метрика | Подозрительно | Почему |
| :-- | :-- | :-- |
| Sharpe | > 3 | кривая подогнана под шум |
| Max drawdown | < 5 % | реальные рынки дают жирные хвосты; расширьте окно на 2020 и 2022 годы |
| Число оптимизированных параметров | > 30 | каждая степень свободы гнётся под исторический шум |
| Число сделок | < 100 | одна удачная серия держит всю кривую |
| Win rate | > 80 % | стоп слишком широк относительно тейка; проверьте R:R |
| Profit factor | > 4 | чаще всего look-ahead bias или нереалистичные исполнения |
| Самая длинная серия убытков | < 3 | кривую «прилизал» оптимизатор |

### Честные издержки

Считаем в бэктесте:

- комиссию брокера (по рынку РФ — примерно 0,01–0,3 % от оборота) и биржевой
  сбор;
- спред: вход/выход по bid/ask, а не по mid или close;
- проскальзывание: минимум 1 тик, для market-заявок — по объёму в стакане;
- НКД для облигаций, ГО для фьючерсов;
- налоги (для РФ — см. раздел 4.7).

## 4.3. Метрики и как их читать

### Expectancy (математическое ожидание) — база

```
Expectancy = (WinRate × AvgWin) − (LossRate × AvgLoss)
```

Удобно выражать в **R** (кратно риску на сделку):

| Expectancy | Вердикт |
| :-- | :-- |
| > 0.5 R | крепкая стратегия |
| 0.2 – 0.5 R | приемлемо, но нужна валидация на большем числе сделок |
| 0 – 0.2 R | хрупко, издержки съедят |
| < 0 R | не торгуем |

Считать минимум на 100 сделках, лучше на 200+.

### Profit factor

```
PF = Σ прибылей / |Σ убытков|
```

- < 1.5 — слабо, издержки добьют;
- 1.5–1.75 — минимум;
- > 4 — подозрительно.

### Sharpe / Sortino / Calmar

| Метрика | Знаменатель | Ориентир |
| :-- | :-- | :-- |
| Sharpe | общая волатильность | > 0.5 реалистично, > 1.0 хорошо, > 2.0 — проверить на подгон |
| Sortino | только downside-волатильность | > 1.0 хорошо, > 2.0 очень хорошо |
| Calmar | максимальная просадка | > 0.5 приемлемо, > 1.0 сильно |

Sharpen и Calmar читают **вместе**: высокий Sharpe при глубокой просадке означает
неконтролируемый хвостовой риск.

### Прочие

- **Max drawdown** — худшая просадка от пика; главный «психологический» и
  инфраструктурный лимит.
- **Recovery factor** = чистая прибыль / MaxDD; > 1 — база, > 2 — устойчивость.
- **Ulcer Performance Index** — доходность с учётом глубины и длительности
  просадок.
- **Win rate** без R:R неинтерпретируем: 45 % при 2:1 лучше, чем 80 % при 1:3.
  Безубыточность: при R:R 1:2 нужно 33,3 % выигрышей, при 1:3 — 25 %.

### Оценка «правдоподобия» готовой системы

Credible-профиль на многолетней выборке: Sharpe ≈ 1.5, MaxDD ≈ 20 %,
win rate ≈ 50 %, PF ≈ 1.8, Calmar ≈ 1.2.

## 4.4. Размер позиции и риск-менеджмент

### Базовая формула

```
Size = (Капитал × Риск %) / |Entry − Stop|
```

Пример: капитал 50 000, риск 1 % = 500, вход 100, стоп 96 ⇒ риск на штуку 4 ⇒
125 штук, номинал 12 500 (25 % счёта), но **под риском ровно 1 %**.

### Методы

| Метод | Формула/суть | Когда |
| :-- | :-- | :-- |
| **Fixed fractional** | фиксированный % капитала под риском (1–2 %) | по умолчанию. Автоматически масштабируется, переживает 50+ убыточных сделок |
| **Fixed dollar** | фиксированная сумма на сделку | простые случаи, не масштабируется |
| **Kelly** | `K = W − (1 − W) / R` или `f* = (bp − q)/b` | только при стабильной статистике (200+ сделок) |
| **Fractional Kelly** | 1/4–1/2 от Келли, потолок 2–5 % | рабочий компромисс |
| **ATR-based** | стоп и размер по волатильности | адаптация к режиму |
| **Kelly-lite** | по скользящей 6-месячной статистике + автоснижение при просадке > 15 % | продвинутый вариант |

### Жёсткие правила

- Риск на сделку — **1–2 %**, не больше. 1 % достаточно агрессивно, чтобы
  компаундиться, и достаточно консервативно, чтобы пережить 10+ убыточных
  сделок подряд.
- **1 % — это 1 %, независимо от уверенности.** Робот именно для того и нужен,
  чтобы убрать «уверенность» из уравнения.
- Не рисковать одной и той же суммой при росте счёта: 2 % от 20 000 — это 400,
  а не 200.
- R:R минимум **1:3** в стратегии с низким win rate; при 25 % выигрышей 3:1 уже
  прибыльно.
- Диапазон «никогда»: < 1 % и > 5 % на сделку.
- При просадке > 15 % — автоматическое снижение риска до восстановления.

### Типичные ошибки сайзинга

1. Считать размер до стопа, а не после.
2. Менять процент «по настроению» и уверенности.
3. Не учитывать лотность MOEX (нельзя купить 37 акций, если лот 100) —
   округляем **вниз** до целого числа лотов и проверяем, что риск не превысил
   лимит.
4. Игнорировать корреляцию: 5 позиций по 1 % в одном секторе — это не 5 %, а
   близко к одному большому риску.
5. Забывать про НКД, ГО и комиссию в оценке риска сделки.

## 4.5. AFML (López de Prado) — что взять

Книга *Advances in Financial Machine Learning* — фактический стандарт
индустрии по работе с финансовыми данными. Ключевое: финансовые данные
**нестационарны, зашумлены, не IID и рефлексивны** — обычный ML на них
сразу даёт ложные открытия.

| Идея | Суть | Зачем |
| :-- | :-- | :-- |
| **Информационные бары** | tick / volume / dollar bars вместо временных | сглаживают нестационарность потока сделок |
| **Triple-barrier labeling** | на каждое наблюдение три барьера: take-profit, stop-loss, время. Кто сработал первым — тот и метка (−1 / +1 / 0 или знак доходности) | метка согласована с реальной торговлей, а не с «ценой через 5 дней» |
| **Meta-labeling** | первичная модель даёт сторону (высокий recall), вторичная — бинарное «ставить или нет» и размер | максимизирует F1, отделяет direction от sizing |
| **Sample weights** | вес наблюдения по уникальности и по перекрытию во времени | убирает дублирование перекрывающихся меток |
| **Fractional differentiation** | минимальное нецелое дифференцирование, дающее стационарность | сохраняет «память» ряда, не выкидывая информацию, как при обычном diff |
| **Purged k-fold + embargo** | чистка train от наблюдений, чьи метки пересекаются с test | убирает look-ahead |
| **CPCV** | N групп, по k в тесте, `C(N,k)` сплитов → много путей | даёт распределение результатов, а не одну кривую; считается PBO |
| **Backtest through CV** | walk-forward как частный случай CV | честная OOS-оценка |
| **Микроструктурные признаки** | последовательности тиков, энтропия, t-тесты серий, фильтр Калмана, объёмный дисбаланс | для внутридневных и HFT-стратегий |

## 4.6. Инфраструктура риска: пять слоёв

Слои намеренно перекрываются: каждый ловит свой тип отказа и остаётся полезным,
когда соседний ошибся. **У них не должно быть общей точки отказа.**

| Слой | Что делает |
| :-- | :-- |
| 1. Лимиты позиции | максимум по инструменту и в агрегате (в лотах), проверка **до** каждой заявки |
| 2. Лимит убытка | по mark-to-market; при пробое — **закрытие книги**, а не просто запрет новых входов |
| 3. Лимит частоты заявок | сдерживает runaway-циклы и retry-штормы |
| 4. Kill switch | внешний, в **другом процессе**; отзывает право выставлять заявки, отменяет открытые, закрывает позиции |
| 5. Реконсиляция | сверка внутреннего состояния с брокером; расхождение — остановка торговли |

Порядок постройки:

1. Лимиты позиции — до первой живой заявки.
2. Kill switch, внешний, протестированный — до первой живой заявки.
3. Реконсиляция, ежедневно — с первого дня.
4. Лимит убытка с закрытием книги — до масштабирования выше одного лота.
5. Лимит частоты — до любой стратегии, стреляющей пакетами.

### Kill switch: как надо

- Отдельный процесс, отдельные креды, желательно другая инфраструктура.
- Флаг внутри стратегии **не работает**: стратегия может быть в дедлоке или в
  бесконечном цикле — именно в этот момент её и надо убить.
- Алгоритм: (1) отозвать право выставлять заявки; (2) отменить все открытые —
  **запросив их у брокера**, а не из внутренней записи; (3) закрыть позиции по
  позиции от брокера; (4) перепроверить, что позиции нулевые; (5) оповестить.
- **Автоматического восстановления нет** — включается только человек.
- Kill switch, который рапортует об успехе без проверки, хуже отсутствия:
  он снимает ощущение срочности.

### Pre-trade проверки (блокируют заявку до брокера)

- максимум количества и нотионала на заявку;
- максимум результирующей позиции, gross/net exposure, working orders;
- проверка отклонения цены от свежих рыночных данных;
- разрешённые инструменты, классы активов, типы заявок, сессии, TIF;
- покупательная способность, маржа, доступность шорта, права счёта;
- **защита от дублей** по стабильному клиентскому идентификатору заявки;
- лимиты частоты заявок и сообщений.

Проверки применяются к **каждому** пути отправки: ретраи, замены, выходы,
плановые действия, ручные операции.

### Мониторинг

- подтверждения, частичные исполнения, отказы, отмены, экспирации, замены;
- сравнение внутреннего состояния с открытыми заявками, позициями и балансом
  брокера — потоки экономят время, но после реконнекта возможны пропуски,
  поэтому нужна периодическая сверка;
- алерты на «застывшие» данные, отвалившиеся стримы, задержки цикла стратегии,
  сбои heartbeat, повторные отказы, аномальный объём заявок, нарушения лимитов;
- хранение меток времени, входов, решений, заявок, ответов брокера и версий конфига —
  без этого разбор инцидента невозможен.

**Отсутствие подтверждения ≠ разрешение отправить ещё одну заявку.** Это
«неизвестное состояние», и обрабатывается оно сверкой.

### Типичные расхождения при сверке

| Расхождение | Вероятная причина |
| :-- | :-- |
| мы в лонге, у брокера пусто | заявка, которую считали исполненной, отклонена или отменена |
| у нас пусто, у брокера лонг | исполнение пришло после реконнекта и не обработано |
| количества отличаются на часть | частичное исполнение |
| исполнения сходятся, позиция нет | корпоративное событие, экспирация, ручное вмешательство |

### Дополнительные слои (для серьёзного масштаба)

- проверки целостности логики стратегии: NaN, отрицательные цены, деление на
  ноль, некорректные значения индикаторов;
- PnL / exposure / order-rate / latency kill switch'и;
- chaos-тестирование: fault injection, искусственная задержка, «испорченный»
  фид, флуд заявками.

## 4.7. Специфика российского рынка

### Расписание Московской биржи (фондовый рынок, МСК)

| Период | Время | Особенности |
| :-- | :-- | :-- |
| Аукцион открытия | 06:50–06:59 | заявки принимаются, не исполняются; расчёт цены открытия |
| Утренняя сессия | 07:00–09:49 | бумаги из IMOEX и самые ликвидные; ликвидность ниже |
| Аукцион открытия основной сессии | 09:50–09:59 | формирование цены открытия |
| **Основная сессия** | 10:00–18:49 | все инструменты, максимальные объёмы |
| Аукцион закрытия | 18:50–18:59 | формирование цены закрытия |
| Аукцион открытия вечерней сессии | 19:00–19:04 | — |
| Вечерняя сессия | 19:05–23:49 | ограниченный список бумаг, выше волатильность |

- **Срочный рынок:** с 23 марта 2026 г. — единая торговая сессия 09:50–23:50,
  промежуточный клиринг в 14:00 отменён, единственная клиринговая сессия
  23:50–00:30.
- **Валютный рынок:** 07:00–23:50 единой сессией, технический перерыв
  04:00–06:50.
- **Выходные:** торги выходного дня относятся к **следующему рабочему дню** —
  покупка в субботу рассчитается во вторник (T+1 от понедельника).
- **Режим расчётов Т+1** — с 31.07.2023 для акций и облигаций. Комиссия
  взимается в день сделки (T0). Расписание торгов и допуск инструментов не
  изменились.

Практика для робота: торговое окно стратегии задаём явно, торги на аукционах
отключаем по умолчанию (там запрещены рыночные заявки и возможны аномальные
цены), для «вечерних» данных помним про низкую ликвидность.

### Класс-коды

`TQBR` (акции), `TQOB` (облигации), `TQTF` (фонды), `SPBFUT` (фьючерсы),
`SPBOPT` (опционы), `CETS` (валюта). SPB Exchange — `SPBRU` (два пула
ликвидности: внутренний и внешний; внешний подключается к 14:30 МСК).

### Налоги (физлица, РФ)

- **НДФЛ с дохода от продажи бумаг:** 13 % при совокупном доходе до 2,4 млн ₽
  за год, 15 % — с суммы сверх порога.
- **Дивиденды:** 13 / 15 %; прогрессивная шкала до 22 % (введённая с 2025 г.) на
  дивиденды **не распространяется** — ставка ограничена 15 %.
- **Купоны по облигациям:** облагаются, по ним доступны льготы по ИИС.
- **ИИС-3** (единственный тип, открываемый с 2024 г.):

  | Параметр | Значение |
  | :-- | :-- |
  | Вычет на взнос | 13–22 % с базы до 400 000 ₽/год (до 52 000 ₽ к возврату) |
  | Освобождение прибыли | до 30 млн ₽ совокупно при закрытии |
  | Минимальный срок | 5 лет (с 2027 г. — 6 лет, далее +1 год в год до 10 лет к 2031 г.) |
  | Лимит взноса | нет (было 1 млн ₽/год у старых типов) |
  | Счетов одновременно | до 3, льготы суммируются |

  Нюансы: вычет на взнос нельзя получить за год закрытия счёта; закрытие одного
  из ИИС-3 закрывает вычеты по остальным; дивиденды на ИИС-3 облагаются у
  источника и через вычет не возвращаются.

- Брокер как налоговый агент считает налог сам; декларация нужна для вычета на
  взнос, если не оформлять его через брокера.

**Следствие для бэктеста:** интрадей-стратегия с большим числом сделок платит
налог с каждой прибыльной сделки, а убытки переносятся иначе, чем в «чистой»
математике. Считаем налог в симуляции, иначе результат завышен.

### Издержки

- Комиссия брокера — примерно 0,01–0,3 % от оборота (зависит от тарифа).
- Биржевой сбор — часто включён в тариф либо порядка 0,015 %.
- Возможны: депозитарные, за ведение счёта, за маржинальное кредитование и
  перенос позиций.
- В **песочнице** T-Invest комиссия ровно **0,05 %** и налоги не считаются —
  поэтому результаты песочницы оптимистичнее реальности.

## 4.8. Чек-лист готовности стратегии к реальным деньгам

- [ ] Гипотеза сформулирована письменно **до** работы с данными.
- [ ] Параметров ≤ 5, каждый экономически обоснован.
- [ ] Hold-out открывался ровно один раз.
- [ ] Пройден walk-forward; итоговая кривая склеена только из OOS.
- [ ] Посчитаны DSR и PBO; DSR > 0.95, PBO < 0.30.
- [ ] ≥ 100 сделок, лучше ≥ 200, покрыто минимум два волатильных режима.
- [ ] Издержки: комиссия + сбор + спред + проскальзывание + НКД + налоги.
- [ ] Известны и зашиты: MaxDD, ожидаемая серия убытков, Sharpe/Sortino/Calmar.
- [ ] Размер позиции: 1–2 % риска, потолок в лотах и в нотионале.
- [ ] Лимиты: заявка, позиция, дневной убыток, частота заявок.
- [ ] Kill switch в отдельном процессе, протестирован на стенде.
- [ ] Реконсиляция с брокером ежедневно, алерты на расхождения.
- [ ] Идемпотентность заявок: клиентский ключ сохраняется до отправки.
- [ ] Прогон в песочнице ≥ 2 недель без вмешательств.
- [ ] Стартовый капитал — тот, который не жалко потерять.
