# Инструкция по управлению системой Red-Bot Investment и «Синтетический трейдер»

## 1. Подготовка и первый запуск

### 1.1. Установка окружения (Python 3.14 + `uv`)
```bash
uv sync --all-extras
```

### 1.2. Сохранение токена T-Invest API
Токен никогда не хранится в коде или git-репозитории. Сохраните его в системное хранилище ОС (Keyring) или передайте через переменную окружения:
```bash
# Вариант 1: через системный Keyring ОС
uv run redbot secrets set-token

# Вариант 2: через переменную окружения
export TBANK_API_TOKEN="t.ваш_токен_t_invest"
```

### 1.3. Первичная инициализация базы данных DuckDB
Создаёт схему таблиц, дефолтную корзину инструментов (`SBER`, `LKOH`, `GAZP` + эталон `IMOEX`) и стартовую конфигурацию стратегии `v1`:
```bash
uv run redbot db bootstrap
```

## 2. Управление через интерфейс командной строки (CLI)

| Команда | Описание |
|---|---|
| `uv run redbot run --mode sandbox` | Запуск торгового цикла и Web GUI (по умолчанию на `http://0.0.0.0:8080`) в контуре песочницы T-Invest. |
| `uv run redbot run --mode backtest` | Запуск Web GUI в полностью изолированном контуре бэктеста (без сетевых обращений к брокеру). |
| `uv run redbot run --mode live` | Запуск в боевом контуре (потребует интерактивного подтверждения). |
| `uv run redbot backtest --ticker SBER --timeframe 1h --bars 96 --horizon 8` | Запуск вероятностного бэктеста и валидации «Синтетического трейдера» в терминале с выводом `Return`, `MaxDD`, `OOS Sharpe`, `P(trend)`, `P(up\|trend)`, `P(break<=H)`, `PBO` и `DSR`. |
| `uv run redbot history-backfill --instrument-id <UID_OR_FIGI> --years 2020,2021,2022,2023,2024,2025` | Скачивание годовых ZIP-архивов минутных свечей (`history-data`) и автоматическая агрегация в иерархию `5m`, `15m`, `1h`, `4h`, `1d`. |
| `uv run redbot catalog-refresh --types share,etf,futures` | Обновление локального справочника инструментов из `InstrumentsService` T-Invest API. |
| `uv run redbot db stats` | Статистика количества строк в таблицах DuckDB и объёма Parquet-архива по слоям (`hot`, `warm`, `cold`). |
| `uv run redbot db doctor [--repair]` | Проверка целостности корзины инструментов, каталога и зависших торговых планов. |

## 3. Управление через Web GUI (Панель управления Red-Bot)

После запуска `uv run redbot run` откройте браузер по адресу `http://localhost:8080`.
Для быстрого перехода между любыми экранами, тикерами и действиями нажмите **`Ctrl+K`** (или **`Cmd+K`**) — откроется командная палитра.

### 3.1. Группа «ТОРГОВЛЯ»
1. **Обзор (`/`)**:
   - Показывает текущий контур (`LIVE` / `SANDBOX` / `BACKTEST`), состояние планировщика, стоимость портфеля, свободный кэш, карточки активных торговых планов (`ACTIVE` / `PENDING`) и живую ленту последних решений бота.
2. **Мысли бота (`/reasoning`)**:
   - Визуализирует воронку принятия решений (сколько инструментов отсеяно по тренду `1D`, по сетапу `1H`, по таймингу `VWAP`, по фильтру издержек или по риск-лимитам) и таблицу покрытия корзины.
3. **Рынок (`/chart` или `/chart/<uid>`)**:
   - Свечной график Lightweight Charts с переключателем таймфрейма (`1D`, `1H`, `1m`), уровнями Фибоначчи, линией относительной силы `IMOEX`, биржевым стаканом (Bids/Asks) и пошаговой расшифровкой последнего решения по бумаге.

### 3.2. Группа «СТРАТЕГИЯ»
4. **Инструменты (`/instruments`)**:
   - Управление рабочей корзиной бумаг: поиск по локальному каталогу T-Invest (акции, фонды, фьючерсы, валюта), добавление тикеров в корзину, включение/отключение торговли по отдельной бумаге.
5. **Стратегия (`/strategy`)**:
   - **Веса Confluence и порог входа**: настройка весов 7 модулей (`regime_alignment`, `trend_d1`, `setup_h1`, `fibonacci`, `volume`, `relative_strength`, `orderbook`) и минимального порога входа (`0.00 — 1.00`).
   - **Архитектура «Синтетического трейдера»**: сводка иерархии `1D/4H → 1H → 15m/5m` и 13 нормированных опорных скользящих средних (`SMA 5..200`, `EMA 8..144`).
   - **Параметры исполнения и TTL (`POST /strategy/execution`)**: редактирование комиссии, минимального множителя цели к издержкам, максимального времени удержания позиции (TTL в часах) и разрешения контртрендовых входов. Каждое сохранение создаёт новую версию `StrategyConfig` (`v2`, `v3`, …).
6. **Риск (`/risk`)**:
   - Управление риском на сделку (`%`), максимальным ноционалом позиции (`₽`) и дневным лимитом просадки (`%`).

### 3.3. Группа «УЧЁТ»
7. **Журнал (`/journal`)**:
   - История закрытых сделок с оценкой качества выходов (`MAE` / `MFE`, вердикты `GOOD_EXIT`, `PREMATURE_EXIT`, `OVERSTAYED`) и Канбан-доска торговых гипотез (`PROPOSED → TESTING → CONFIRMED / REJECTED`).
8. **Бэктест «Синтетический трейдер» (`/backtest`)**:
   - **Форма конфигурации прогона**:
     - Выбор инструмента корзины и рабочего таймфрейма (`5m`, `15m`, `1h`, `4h`, `1d`);
     - Глубина выборки (баров) и начальный капитал (`₽`);
     - Параметры тройного барьера: горизонт $H$, множители $k_{\text{tp}} \cdot \text{ATR}$ и $k_{\text{sl}} \cdot \text{ATR}$;
     - Пороги риск-движка: порог режима $P(\text{trend}) > a$, порог направления $P(\text{up} \mid \text{trend}) \ge b$, порог аварийного выхода $P(\text{break} \le H)$;
     - Глубина симметричных деревьев CatBoost (`4..6`), комиссия брокера и проскальзывание (в базисных пунктах `bps`).
   - **Как интерпретировать блок результатов**:
     - **Триада вероятностей**: если $P(\text{trend}) \le a$, риск-движок блокирует вход (`SIDEWAYS_NOISE_P_TREND_BELOW_A`). Если $P(\text{trend}) > a$ и $P(\text{up} \mid \text{trend}) \ge b$, размер позиции масштабируется пропорционально $(1 - P(\text{break}))$ и целевой волатильности.
     - **HMM Гамильтона и $\ell_1$-фильтр**: при доминировании состояния `PANIC` входы автоматически запрещаются (`HMM_PANIC_REGIME_BAN`).
     - **Статистический гейт (Раздел 5)**: проверяйте, чтобы **PBO (CSCV)** был $< 50\%$, **Deflated Sharpe Ratio (DSR)** $\ge 50\%$, а $p$-value теста **Hansen SPA** подтверждал превосходство над случайным блужданием.
     - **Сравнение с 3 эталонами**: стратегия сопоставляется с `Buy & Hold IMOEX`, `MA Crossover (8/21)` и `RSI(14) Bot` с учётом тех же комиссий. Статус `Shadow/Sandbox Ready: ДА` выставляется только при прохождении статистического гейта и обыгрывании бенчмарков.
     - **MLOps и PSI-дрейф**: при `PSI >= 0.20` загорается индикатор `CRITICAL_RETRAIN`, сигнализирующий о смещении распределения признаков и необходимости переобучения на свежем окне.

### 3.4. Группа «СИСТЕМА»
9. **Пульт (`/control`)**:
   - Оперативное управление планировщиком (Пауза / Возобновление / Принудительный цикл), аварийная кнопка **Kill Switch** (остановка торговли с отменой активных заявок) и живой поток системных логов.
10. **Хранилище (`/admin/storage`)**:
    - Диаграмма слоёв хранения (`Hot` / `Warm` / `Cold`), запуск ротации и архивации в Parquet, создание/восстановление резервных копий и безопасная `SELECT`-консоль DuckDB.
11. **Счёт и режим (`/settings`)**:
    - Переключение контура (`SANDBOX` / `LIVE` / `BACKTEST`), управление песочными счетами T-Invest (создание счёта, пополнение тестового баланса `SandboxPayIn`) и проверка статуса токена.
